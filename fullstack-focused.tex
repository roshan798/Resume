\item \href{https://github.com/roshan798/pizza-delivery-app}{\textbf{Pizza Delivery Platform}}
  \hfill \href{https://mern-pizza-app.cyou}{mern-pizza-app.cyou}\\
  End-to-end, multi-tenant pizza ordering platform spanning microservices
  backend and polished React frontends --- built and deployed to production.
  \begin{itemize}
    \itemsep -3pt
    \item \textbf{Backend:} 5 independently deployed \textbf{Node.js} microservices.
          Auth Service uses \textbf{PostgreSQL} with JWT access + refresh token
          rotation and RBAC (Admin / Manager / Customer); services validate tokens
          locally, removing Auth as a synchronous dependency.
    \item \textbf{Event-driven:} \textbf{Kafka} decouples Catalog from Order
          Service --- catalog mutation events keep Order's local price cache
          in sync, so checkout validates prices without cross-service HTTP calls.
          A single ORDER\_PLACED event fans out to both WebSocket and Notification
          services independently.
    \item \textbf{Payments \& real-time:} \textbf{Stripe} PaymentIntent with
          webhook verification for card orders; \textbf{Socket.io} pushes live
          status updates (Confirmed $\to$ Delivered) to both customer and
          manager UIs without polling.
    \item \textbf{Frontend:} Customer storefront in \textbf{Next.js 14}
          (App Router, SSR) with dynamic pizza customization and Stripe checkout;
          Admin Dashboard in \textbf{React + Vite} with real-time order
          notification panel, product/topping CRUD, and status management.
    \item \textbf{Infra:} Backend on \textbf{AWS EKS}; \textbf{ArgoCD} GitOps
          with GitHub Actions; NGINX Ingress for SSL and routing;
          frontends on \textbf{Vercel}.
    \item \textbf{Tech:} Node.js \(\cdot\) PostgreSQL \(\cdot\) MongoDB \(\cdot\)
          Kafka \(\cdot\) Stripe \(\cdot\) Socket.io \(\cdot\) AWS S3 \(\cdot\)
          Kubernetes \(\cdot\) Docker \(\cdot\) ArgoCD \(\cdot\) Next.js \(\cdot\) React
  \end{itemize}
